I. Device enumeration

When you plug a USB device in, the host performs a fixed sequence of control transfers on endpoint 0.
GET_DESCRIPTOR (Device)	        identify the device
GET_DESCRIPTOR (Configuration)  describe interfaces/endpoints
SET_ADDRESS	                    assign USB address
SET_CONFIGURATION           	enable the device

II. Descriptrs.
const uint8_t DeviceDescriptor[] = {
    0x12,        // bLength (18 bytes)
    0x01,        // bDescriptorType = Device
    0x00, 0x02,  // bcdUSB = USB 2.0

    0xFF,        // bDeviceClass = Vendor specific
    0x00,        // bDeviceSubClass
    0x00,        // bDeviceProtocol

    0x40,        // bMaxPacketSize0 = 64 bytes

    0x34, 0x12,  // idVendor  = 0x1234
    0x01, 0x00,  // idProduct = 0x0001
    0x00, 0x01,  // bcdDevice = 1.00

    0x00,        // iManufacturer
    0x00,        // iProduct
    0x00,        // iSerialNumber

    0x01         // bNumConfigurations
};

const uint8_t ConfigurationDescriptor[] = {
    // Configuration Descriptor
    0x09,        // bLength
    0x02,        // bDescriptorType = Configuration
    0x12, 0x00,  // wTotalLength = 18 bytes

    0x01,        // bNumInterfaces
    0x01,        // bConfigurationValue
    0x00,        // iConfiguration

    0x80,        // bmAttributes = Bus powered
    0x32,        // bMaxPower = 100 mA

    // Interface Descriptor
    0x09,        // bLength
    0x04,        // bDescriptorType = Interface

    0x00,        // bInterfaceNumber
    0x00,        // bAlternateSetting

    0x00,        // bNumEndpoints (only EP0 exists)

    0xFF,        // bInterfaceClass = Vendor specific
    0x00,        // bInterfaceSubClass
    0x00,        // bInterfaceProtocol

    0x00         // iInterface
};

!: endpoint 0 is implicit and does not appear in descriptors

III. Barebones USB firmware.
main()
{
    enable_usb_hardware();
    attach_device();

    while(1)
    {
        if (USB interrupt)
            handle_usb();
    }
}

Interrupt handler typically handles
* USB reset
* SETUP packet received
* endpoint events

SETUP parser outline:
if (request == GET_DESCRIPTOR)
    // Q: are device and configuration descriptors requested separately? probably yes, since device D.
    // contains the nubmer of configuration Descriptors
    send descriptor

else if (request == SET_ADDRESS)
    set address

else if (request == SET_CONFIGURATION)
    mark configured

else
    stall endpoint

USB RESET
↓
GET_DESCRIPTOR(Device)
↓
SET_ADDRESS
↓
GET_DESCRIPTOR(Configuration)
↓
SET_CONFIGURATION


V. Endpoint 0

Your EP0 handler only needs to support:

GET_DESCRIPTOR (device)
GET_DESCRIPTOR (configuration)
SET_ADDRESS
SET_CONFIGURATION


VI. Endpoints.

Example endpoint descriptor (part of Configuration D.):
0x07,       // bLength
0x05,       // bDescriptorType = Endpoint
0x81,       // bEndpointAddress
            // 0x80 = IN direction
            // 0x01 = endpoint number 1
0x03,       // bmAttributes = Interrupt
0x08, 0x00, // wMaxPacketSize = 8 bytes
0x01        // bInterval = 1 ms

VII. Interfaces.

One device may expose multiple interfaces (e.g. HID keyboard + CDC)
USB devices are organized like this:

Device
 └── Configuration
      └── Interface(s)
           └── Endpoint(s)

Example:

USB game controller
 └── HID interface
      └── EP1 IN

Or a composite device:

USB device
 ├── CDC interface
 │    ├── EP1
 │    ├── EP2 OUT
 │    └── EP3 IN
 │
 └── HID keyboard interface
      └── EP4 IN

Interfaces are explicitly declared in descriptors, e.g.:
0x09,       // bLength
0x04,       // bDescriptorType = Interface
0x00,       // bInterfaceNumber
0x00,       // bAlternateSetting
0x01,       // bNumEndpoints
0x03,       // bInterfaceClass = HID
0x00,       // bInterfaceSubClass
0x00,       // bInterfaceProtocol
0x00        // iInterface

VIII. HID Report Descritor

Retrieved by the host separately via
GET_DESCRIPTOR(HID_REPORT)

IX. IN Endpoint
The host always initiates data transfer (by sending an IN token)
The device can send NAK if no data is available (e.g. joystick state hasn't changed) to reduce traffic
